# Runic Command Line 0.6.0-preview.4

This candidate tightens typed recovery data and generated result contexts, makes
errors name their cause, links help to the release you use, publishes the
framework text keys and removes common boilerplate. It is not published yet.
Some output defaults change; see [Install and migrate](#install-and-migrate).

## Typed recovery data and result contexts

- `CommandFailureData.Create` reports the reader's `CommandProtocolException`
  kinds: data nested deeper than 24 objects/arrays raises
  `failure-data-depth-limit`, and serializer, converter and encoding failures
  (for example unsupported types) raise `invalid-failure-data` instead of
  escaping as other exceptions. Handlers that catch `CommandProtocolException`
  no longer fall through to the generic host failure.
- `CommandFailureData.Create` refuses invalid UTF-16 (an unpaired surrogate) in
  any string value or property name, including dictionary keys, with
  `invalid-failure-data`. System.Text.Json previously replaced such strings with
  U+FFFD, silently altering data the reader would have refused. Valid data,
  including surrogate pairs, serializes byte-for-byte as before.
- Readers measure the 64 KiB `fault.data` payload bound on its compact form, as
  producers do. Pretty-printed payloads from external producers are no longer
  rejected because of insignificant whitespace.
- Generated `[CommandResult]` codecs expect a System.Text.Json-generated `Default`
  only for partial `[JsonSerializable]` contexts the JSON source generator can
  complete (concrete, non-generic, all containing types partial, no hand-written
  `GetTypeInfo`, `GeneratedSerializerOptions` or `Default`). Other contexts keep
  their constructor path.

## Errors name their cause

- The source generator reports catalog rules that attributes can break at build
  time, located at the declaration: a required argument after an optional one
  (`RCLI9035`, previously only the runtime `RCLI0015` at startup), `Minimum` or
  `Maximum` on a non-numeric parameter (`RCLI9036`), `MustExist` without a path
  kind (`RCLI9037`), a `Requires`/`ConflictsWith` entry that is a spelling, the
  option itself or an argument (`RCLI9038`), an unknown relationship ID
  (`RCLI9039`, a warning because a global option may supply it) and a nested
  `[DefaultCommand]` (`RCLI9040`). `RCLI9028` now only means missing
  `[CommandResult]` metadata and explains that an `int` result is payload, not
  the exit code; a non-context type is `RCLI9041`, a context without the result
  type is `RCLI9042`, and an empty payload type is `RCLI9005`.
- `CommandCatalogValidationException.Message` lists each issue's code, command
  path and message (up to 20), and catalog messages name the items involved.
- Handler, binder and scope exceptions are written to stderr, with their stack
  traces, when a debugger is attached, `DOTNET_ENVIRONMENT=Development` or
  `RUNIC_COMMANDLINE_DEBUG=1`. The human `RCLI5000` line hints at this when no
  `ExceptionObserver` is set (key `hints.RCLI5000`). The JSON frame is
  unchanged.
- Generated help shows enum defaults by member name (`[default: Careful]`), not
  by number.
- Value errors name the option spelling or `<ARGUMENT>` and the expected type:
  "--limit requires a whole number." (`RCLI2005`). Generated binders check each
  value in the order conversion, declared range, `[ValidateWith]` validator: a
  non-number is no longer reported as out of range, a validator still never
  sees an out-of-range value, and ranges read "--limit requires a number between
  1 and 50." (`RCLI2002`). Hand-written binders get the range check after they
  bind successfully. Both faults carry one `binding` diagnostic (kinds such as
  `invalid-integer`, `out-of-range`, `below-minimum`), which JSON readers see in
  the existing `diagnostics` array.
- An invalid choice lists the allowed values ("--format must be one of: json,
  csv."), except for sensitive parameters and very long lists
  (`diagnostics.invalid-choice-hidden`). An invalid `--output` value reads
  "--output must be human or json.", and the diagnostic carries the option name
  as its argument.
- A bad value from an environment fallback names the variable: invalid flags read
  "CAUSE_VERBOSE must be true/false, yes/no or 1/0 for --verbose." (`RCLI1014`,
  arguments now option and variable), and conversion errors add a new `RCLI2006`
  information diagnostic, `environment-value-source`. Values are never echoed.
- With a default command, a mistyped command that resembles a real one reports
  `RCLI1002` with "Did you mean 'list'?" instead of an unexpected argument of the
  default command.

## Text keys and localization

- New `CommandTextKeys` lists every framework text key and its argument order,
  with `Diagnostic(kind)` and `Fault(code)` helpers. See
  [Text keys](https://github.com/Runic-Artifex/runic-cli-sdk/blob/v0.6.0-preview.4/docs/guides/command-line/text-keys.md).
- New messages, including value errors, resolve through `diagnostics.{kind}`
  keys with ordered arguments such as the parameter and bounds. A diagnostic
  whose key has no translation falls back to an existing `faults.{code}`
  translation.
- "Did you mean" suggestions use the new keys
  `diagnostics.unknown-option-suggestion` and
  `diagnostics.unknown-command-suggestion`, so they can be translated.
- `CommandTextContext.ValidateDescriptionKeys` reports `DescriptionKey` values
  that do not resolve (`RCLI0023`), and help prints them as warnings in debug
  mode.

## Help links

- Diagnostic help links from the generator (`RCLI9xxx`) and catalog validation
  messages open the diagnostics catalog at the release tag (`v<version>`)
  instead of `main`. The
  [diagnostics catalog](https://github.com/Runic-Artifex/runic-cli-sdk/blob/v0.6.0-preview.4/docs/guides/command-line/diagnostics.md)
  documents every `RCLI` code.
- New `CommandFault.HelpUri` and `CommandDiagnostic.HelpUri` (absolute https
  links). They appear as the optional `helpUri` member in JSON envelopes and as
  a `Help for <code>: <link>` line in human output. Readers of
  `runic.commandline/1` that predate this change ignore the member. Redaction of
  messages, details and arguments is unchanged.
- Packed READMEs link to the release tag.
- The README in the `Runic.CommandLine` NuGet packages no longer turns
  backslashes into slashes when the packages are packed on Linux, so the C#
  samples show `"\n"` and `"ü"` again.

## Less boilerplate

- `CommandScopes.FromServices`, `CommandScopes.Create` and `CommandServices`
  create invocation scopes without a custom `ICommandExecutionScopeFactory`. For
  Microsoft.Extensions.DependencyInjection, use
  `CommandScopes.Create(provider.CreateAsyncScope, s => s.ServiceProvider)`.
- `CommandLineHostingAdapter(CommandApp)` and `RunAsync(decision)` run hosted
  decisions, which expose `MatchedPath`, `MatchesKnownCommand` and
  `IsCommandLineRequest`.
- `[CommandGroup]` and `CommandCatalogBuilder.Group` describe auto-created
  command groups. The new error diagnostic is `RCLI9043`.
- `RCLI9022` no longer reports `CancellationToken cancellationToken = default`,
  so the token can come last, as CA1068 recommends.
- `ICommandConsole` gains string and line extension methods.
- Exit codes are documented in the README and on `CommandExitCodes`.

## New public API

- `CommandTextKeys`, `CommandTextContext.ValidateDescriptionKeys`,
  `CommandFault.HelpUri`, `CommandDiagnostic.HelpUri`, `CommandScopes`,
  `CommandServices`, `CommandLineHostingAdapter`, `[CommandGroup]` and
  `CommandCatalogBuilder.Group`.
- `GeneratedCommandBinding.Failure<TOptions>` and
  `GeneratedCommandBinding.CheckRange<T>`, used by generated binders.

## Install and migrate

Use .NET 10 and keep `Runic.CommandLine` and the optional
`Runic.CommandLine.Processes`, `Runic.CommandLine.Spectre` and
`Runic.CommandLine.Testing` packages on the same exact version.

- Human output of typed results prints readable rows: booleans print as
  `true`/`false`, lists are comma-joined, and nested objects are indented.
- JSON output writes non-ASCII text unescaped. HTML-sensitive characters,
  control characters, and bidi and zero-width characters remain escaped.
- `CommandApp.Culture` defaults to `CultureInfo.CurrentUICulture` (the display
  language) instead of `CultureInfo.CurrentCulture`.
- A required argument after an optional one now fails the build with
  `RCLI9035` instead of aborting at startup with `RCLI0015`.
