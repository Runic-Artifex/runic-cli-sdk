# Runic Command Line 0.6.0-preview.5

This preview makes a mistyped command in a hosted application suggest the
intended one and names the conflicting definitions in `RCLI0019`. It has no
breaking changes.

## Errors name their cause

- `RCLI0019` for a global option that conflicts with a command's own option now
  names the option ID and both definitions, for example
  `Global option 'force' conflicts with the command-local option of the same ID:
  the global option is --force with aliases [-F], the command-local option is
  --force with aliases [-f]. ...`. The arity is listed when it differs. Only the
  message text changes; the code, location and help link are the same.

## Hosted applications

- A mistyped command in a hosted application is no longer silent. When an
  unknown first word is a close match for a visible command (`lst` for `list`),
  `HostedCommandLineDecision.SuggestedCommand` names it. The launch still
  belongs to the user interface, so document paths keep opening the UI.
  `CommandLineHostingAdapter.WriteSuggestionAsync` writes the standalone
  command line's "Did you mean 'list'?" line to standard error before the host
  opens its UI; it writes nothing for a document path or an empty launch.

## New public API

- `HostedCommandLineDecision.SuggestedCommand`
- `CommandLineHostingAdapter.WriteSuggestionAsync(HostedCommandLineDecision, ICommandConsole?, CancellationToken)`

## Install

Use .NET 10 and keep `Runic.CommandLine` and the optional
`Runic.CommandLine.Processes`, `Runic.CommandLine.Spectre` and
`Runic.CommandLine.Testing` packages on the same exact version,
`0.6.0-preview.5`. No migration is needed from 0.6.0-preview.4.
