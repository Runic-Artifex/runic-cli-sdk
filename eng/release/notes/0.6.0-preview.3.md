# Runic Command Line 0.6.0-preview.3

This candidate adds typed recovery data for external applications and fixes
generated result serialization. It is not published yet.

- Generated `[CommandResult]` codecs use the JSON context's configured `Default`
  instance, preserving naming policies and other source-generation defaults.
  Custom contexts without a `Default` instance retain their constructor path.
- Explicit `CommandFailureData.Create` declarations snapshot application-owned
  failure data using a stable identity and source-generated JSON metadata.
  `FailureWithData` and `FailedWithData` carry it through command execution,
  response conversion and localization. Data is bounded to 64 KiB of UTF-8 JSON
  and 24 nested objects/arrays; it is never truncated.
- The optional `fault.data` extension contains `type` and `payload`. The
  `runic.commandline/1` envelope, nonzero failure exits and null success payload
  fields on failure remain unchanged. Older readers ignore this extension.
- New readers validate the extension and decode only an explicitly requested
  identity through `TryGet`. Unknown identities fall back to the ordinary fault;
  malformed matching data reports a protocol error. Deserialization follows
  the supplied JSON metadata and its serializer settings.

Ordinary fault text and diagnostics remain sanitized. Typed data is intended for
declared domain fields, such as exact recovery paths or branch identities; keep
exception text, logs and unrelated internal state out of these contracts.
