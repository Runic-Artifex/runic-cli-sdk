# Runic Command Line 0.14.0

Command Line 0.14.0 is the first release of the 0.23 release train (Command
Line 0.14.0, then Runic Translations 0.15.0, then Runic SDK 0.23.0). It retires
the `faults.RCLI4001` text key, so every framework key now has a catalog
message, makes the strict JSON reader reject duplicate member names anywhere in
a frame, and makes NativeAOT executables smaller. The public API is unchanged
except that `CommandTextKeys.FaultPromptUnavailable` is now `[Obsolete]`;
package validation against 0.13.0 is clean. Some behaviour changes; the changes
are listed under [Upgrading from 0.13](#upgrading-from-013).

## Upgrading from 0.13

Nothing is removed. These changes can still need action:

| Change | Who is affected | What to do |
| --- | --- | --- |
| The `RCLI4001` fault (a prompt that cannot ask) always shows the text of its `diagnostics.prompt-*` diagnostic. A resolver's `faults.RCLI4001` message no longer replaces the English prompt text, `faults.RCLI4001` is no longer in `CommandTextKeys.All` or `text-keys.json`, and `CommandTextKeys.FaultPromptUnavailable` is obsolete | Applications that defined `faults.RCLI4001`, through Runic Translations' deprecated second override path (`RTR0107`) or their own `ICommandTextResolver` | Override `diagnostics.prompt-requires-terminal`, `diagnostics.prompt-json-output` and `diagnostics.prompt-disabled` instead (argument `prompt`, the question), for example in `translations/overrides/runic-command-line/<locale>.rmf2`. Remove the `faults.RCLI4001` message. |
| The strict reader (`CommandJsonEnvelopeReader`, and the testing helpers built on it) rejects a frame with a duplicate member name anywhere, also inside members it does not know, with `duplicate-property` (Q23, D076.2) | Producers that write a duplicate member inside an unknown member at the root, in `fault` or in a diagnostic; such a frame was accepted before | Write each member name once per object, as protocol §Compatibility requires. Frames without duplicates read as before. |

German text for this release needs `Runic.Translations.CommandLine` 0.15.0.
Each Command Line minor has one adapter release line, released right after it in
the same train:

| Runic.CommandLine | Runic.Translations.CommandLine |
| --- | --- |
| 0.14.x | 0.15.x (Runic.CommandLine `[0.14.0, 0.15.0-0.0)`) |
| 0.13.x | 0.11.x to 0.14.x (Runic.CommandLine `[0.13.0, 0.14.0-0.0)`) |
| 0.12.x | 0.10.x (Runic.CommandLine `[0.12.0, 0.13.0-0.0)`) |
| 0.10.x, 0.11.x | none; 0.9.1 does not accept them (`NU1608`) |
| 0.9.x | 0.9.1 (`[0.9.1, 0.10.0)`); 0.8.0 (`[0.9.0, 0.10.0)`) |

A mismatched pair fails restore with `NU1608`. Translations 0.15 also removes
the deprecated second override path for framework text, so a `faults.RCLI4001`
or other framework-key message in an application's own catalog has no effect
there (`RTR0107`). Before publication, the release train's compatibility gate
(row T, run by the publish workflow) restores and runs this release's packages
with the Translations and Runic SDK candidates, with warnings as errors.

## Duplicate member names are rejected everywhere (Q23, D076.2)

The protocol makes duplicate JSON property names invalid at every level. The reader checked the envelope, the fault,
`fault.details`, `fault.data`, each diagnostic and the whole payload, but not the objects inside members it does not
know, and accepted a frame with one there. It now checks every object of the frame in one pass from the root, before
any other envelope check, and raises `duplicate-property` as before. A frame with a duplicate and another violation
now reports the duplicate. The protocol corpus (`wire-inputs.json`) adds cases for a duplicate inside an unknown
member at the root, in the fault and in a diagnostic.

## RCLI4001 always shows its prompt text (D072.20)

Before 0.14 the built-in catalogs had no `faults.RCLI4001` message, and Runic.CommandLine showed a `faults.RCLI4001`
message from the application instead of the `diagnostics.prompt-*` text whenever that text was the English one. An
application could define it only through Runic Translations' deprecated second override path, which Translations 0.15
removes. Now the fault message is always the diagnostic's message, translated like every other diagnostic, and every
key in `text-keys.json` has a catalog message. Other faults keep `faults.{code}` as the fallback of an untranslated
diagnostic.

## Smaller NativeAOT executables (D072.2)

Nothing changes for applications; the API and the JSON output stay the same.

- `CommandUnit` payloads (`runic.unit/1`) are written as `{}` by a value converter instead of source-generated object
  metadata, which added a `Type.GetConstructor` factory and System.Text.Json's object-serialization code to every
  executable. Reading accepts any JSON object, as before, and rejects other values.
- The framework checks its own enum arguments with range checks instead of `Enum.IsDefined` and
  `Enum.GetValues<T>`, so it no longer reads enum metadata at run time.
- A linux-x64 NativeAOT executable shrinks by 41,200 bytes for a command-line application whose commands return text
  (`examples/command-line/hello-world`: 3,634,216 → 3,593,016 bytes) and by 12,512 bytes for one that also declares
  its own JSON payload types (the NativeAOT smoke: 6,228,968 → 6,216,456 bytes). CI now fails when the smoke's
  linux-x64 executable grows more than 2 % over its recorded size (`tests/native/Runic.CommandLine.AotSmoke/size-budget.json`).

The .NET reflection stack (`System.Reflection.Runtime`, about 160 KB of code plus its metadata) stays in every
executable that writes JSON through a `JsonTypeInfo`: System.Text.Json reads `[JsonDerivedType]` attributes with
`Type.GetCustomAttributes` when it creates any type's metadata, including source-generated metadata for `string`.
A two-line console application that serializes a string through a source-generated context links it too.
