# Runic Command Line 0.10.0

## Usage errors name the missing argument and point to help (#82)

- **Behaviour change:** positional arguments bind left to right. With fewer
  tokens than the required arguments need, `RCLI1005` `missing-argument` names
  the first argument the tokens do not reach. `tool bind w.storyline` for
  `bind <world> <binding>` now reports `binding`; before, it reported `world`,
  the argument that was given. A bounded argument such as `<sources>{1,2}`
  before a required one still leaves the later argument its token. The grammar
  specification states the rule, and its corpus checks the argument of
  `missing-argument` (an optional `arguments` member of corpus diagnostics).
- **Behaviour change:** human output writes each diagnostic and fault as its
  message, without the leading code: `The binding argument is missing.` instead
  of `RCLI1005: A required command argument is missing. (world)`. Codes are
  for programs, which read them from JSON output; a code that has
  documentation still appears on its `Help for {code}: {link}` line. JSON
  output keeps every code, kind, message key and argument.
- A usage error (exit code 2: parse and binding errors, and a prompt that
  cannot ask) in human output ends with the command's usage line and the help
  command to run:

  ```text
  The binding argument is missing.
  Usage: storyline bind <world> <binding> [options]
  Run "storyline bind --help" for more information.
  ```

  `CommandApp`, `CommandLineHostingAdapter` and their default outcome sink
  write these lines; a command's own `humanOutput`, `PresentFrameworkRequest`
  and a custom outcome sink keep writing their own text. JSON output never
  contains them.
- The new text key `hints.usage` (`CommandTextKeys.HintUsage`, argument
  `command`, such as `storyline bind --help`) translates the last line; the
  usage line uses the `help.usage`, `help.command-placeholder` and
  `help.options-placeholder` keys of help.
- The English parse messages name their subject in the sentence instead of a
  trailing `(name)`, for example `The option '--bogus' is not recognized.`,
  `The --encoding option requires a value.` and
  `The command 'bnid' is not recognized. Did you mean 'bind'?`. Their keys
  and arguments are unchanged; [text keys](../../../docs/guides/command-line/text-keys.md)
  lists the new English text. A resolver that translates these keys is
  unaffected.
- **Behaviour change:** the argument of `RCLI1002` `unknown-command` at the top
  level is the token given where the command belongs, after any leading output
  or global options, as `CommandTextKeys.DiagnosticUnknownCommand` describes,
  and is absent when the command line holds only those options. Before, it was
  the first token, so `--format json frob` named `--format`. The code and kind
  are unchanged.

What to do: tests that compare human stderr with `CODE: message` lines need
the new text; compare JSON output, or the diagnostic's `Code`, `Kind` and
`Arguments`, where the exact wording does not matter.
