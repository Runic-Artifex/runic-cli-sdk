# Runic Command Line 0.6.0-preview.6

Unreleased. These notes collect changes merged after 0.6.0-preview.5.

## An alias for the JSON output selector

- `CommandCatalogBuilder.JsonOutputAlias("--json")` declares a flag that stands
  for `--output json`, so an application that already has a `--json` flag keeps
  its users' command lines. The flag takes no value, is recognized wherever the
  selector is (also before the command, never after `--`), maps to a host's
  transport option such as `--runic-output`, and is listed in help ("Same as
  --output json") and in completions. `GeneratedCommandCatalog.Create(builder =>
  builder.JsonOutputAlias("--json"))` declares it for a generated catalog.
- Giving the flag and the selector together is the new usage error `RCLI1016`
  (`conflicting-output-selector`), which names both spellings. The flag twice is
  `RCLI1007`, and the flag with a value is `RCLI1004`.
- A flag spelled `--output`, a command option spelled like the flag, or
  combined catalogs that declare different flags, fail catalog validation with
  the new `RCLI0024`.
- The grammar specification and corpora cover the alias: the fixture catalog
  declares `--json`, with 4 new grammar and 8 new output-classification rows.

## Processes: live output

- `ProcessRunner.RunAsync(request, outputHandler, cancellationToken)` passes a
  child's output to an `IProcessOutputHandler` while it runs: decoded lines
  (`OnLineAsync`) and raw chunks (`OnChunkAsync`), each tagged with its
  `ProcessOutputChannel`. Calls are never concurrent, keep the write order within
  a channel, and between standard output and standard error follow the order in
  which the runner read them. The runner reads on only when the handler's task
  completes, so a slow handler slows the child instead of growing memory. The
  bounded capture in the result is unchanged. A handler that throws terminates the
  child: the result is `ExecutionFailed` with the new `RCLI6009`.
- `IProcessRunner` gains the same overload with a default implementation that
  passes the captured output to the handler after the run, so existing
  implementations and test doubles keep compiling.

## Processes: cancellation reaches the whole process group

These change behavior without an API change:

- On Unix, when the caller has no controlling terminal (a service, a CI job, a
  desktop application) or the request sets the new `DetachFromTerminal`, the
  child starts through `posix_spawn` as the leader of a new process group, or of
  a new session without a controlling terminal. Cancellation and timeout send
  `SIGTERM` to the group, wait up to `DrainGracePeriod` for the child to exit and
  its pipes to close, and then send `SIGKILL` to whatever is left of the group.
  The leader is reaped only after the last signal, so the group ID cannot be
  reused in between. Before, the runner killed the process tree it found at once
  with `SIGKILL`, so a tool had no chance to clean up and a descendant whose
  parent had exited survived. The worst-case wait after cancellation is now twice
  `DrainGracePeriod`.
- A caller with a controlling terminal keeps the child in its own process group
  by default, so ssh, sudo, git or gpg can still prompt and Ctrl+C still reaches
  them; the child gets `SIGTERM` and then a process-tree kill.
- A caller that ignores `SIGCHLD` loses its children's exit codes to the kernel;
  such a run is now `ExecutionFailed` at exit instead of hanging until its
  timeout.
- On Windows, a child joins a job object right after it starts, and
  cancellation and timeout terminate the job as well as the process tree.
- A descendant that holds an output pipe open after the child exited no longer
  loses the output read before the drain grace period ended, and on Windows a
  read blocked on such a pipe is cancelled
  ([#30](https://github.com/Runic-Artifex/runic-cli-sdk/issues/30)).

## Processes: process identity and unattended callers

- `IProcessObserver.OnStarted(ProcessIdentity, DateTimeOffset)` receives the
  child's process ID and, on Unix, its process group ID. Its default calls
  `OnStarted(DateTimeOffset)`, which now has an empty default body, so existing
  observers keep working.
- `ProcessExecutionOptions.NonInteractive` is the default options with closed
  standard input and `DetachFromTerminal`, for desktop applications and
  services: a child that prompts on `/dev/tty` fails instead of waiting.
- `ProcessResult.EnsureCompleted(CancellationToken)` returns the result when the
  child exited with complete captures and throws otherwise:
  `OperationCanceledException` for cancellation, and `ProcessException` with
  `RCLI6010` for a timeout, `RCLI6011` for truncated or cut-off output, or the
  result's own fault.

## New public API

- `CommandCatalogBuilder.JsonOutputAlias(string)`, `CommandCatalog.JsonOutputAlias`
- `CommandTextKeys.HelpJsonOutputAlias` (`help.json-output-alias`) and
  `CommandTextKeys.DiagnosticConflictingOutputSelector`
  (`diagnostics.conflicting-output-selector`)
- `IProcessOutputHandler`, `ProcessOutputLine`, `ProcessOutputChunk`, `ProcessOutputChannel`
- `ProcessRunner.RunAsync(ProcessRequest, IProcessOutputHandler?, CancellationToken)`
- `IProcessRunner.RunAsync(ProcessRequest, IProcessOutputHandler?, CancellationToken)`
- `ProcessIdentity`, `IProcessObserver.OnStarted(ProcessIdentity, DateTimeOffset)`
- `ProcessExecutionOptions.NonInteractive`, `ProcessExecutionOptions.DetachFromTerminal`
- `ProcessResult.EnsureCompleted(CancellationToken)`, `ProcessException`
- `ProcessFaultCodes.OutputHandlerFailed` (`RCLI6009`), `TimedOut` (`RCLI6010`), `OutputIncomplete` (`RCLI6011`)

## Install

Use .NET 10 and keep `Runic.CommandLine` and the optional
`Runic.CommandLine.Processes`, `Runic.CommandLine.Spectre` and
`Runic.CommandLine.Testing` packages on the same exact version,
`0.6.0-preview.6`.
