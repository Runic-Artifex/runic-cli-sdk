# Runic Command Line 0.6.0-preview.2 upgrade notes

## Termination signals cancel gracefully

With `HandleCancelKeyPress = true` (the default), `CommandApp` now handles SIGTERM
and SIGQUIT as well as Ctrl+C (SIGINT). A single SIGTERM no longer terminates the
process immediately: it cancels the invocation's token, and a handler that honors
it returns the configured `Cancelled` exit code. A second signal while the
invocation is still running exits at once with 128 plus the signal number (130 for
Ctrl+C, 143 for SIGTERM, 131 for SIGQUIT).

Handlers that ignore their cancellation token therefore keep running after the
first SIGTERM until a second signal or the service manager's kill timeout. Pass the
token to long-running work. Set `HandleCancelKeyPress = false` to keep the
runtime's default signal handling, for example when an embedding host owns
process signals.

## Help output wraps to the terminal

Built-in help now aligns each section's descriptions in one column and wraps
long descriptions at word boundaries, continuing them under that column. A term
wider than the column, such as a long option name, puts its description on the
next line. Width is counted in terminal cells, so East Asian wide characters
count as two and may break between characters. Lines of a `LongDescription` that
are indented or contain a run of three or more spaces (lists, aligned columns,
code blocks) are printed as written; all other lines wrap, and line breaks in
the source text are kept. Help uses the terminal width less one column on an
interactive console, and 80 columns when output is redirected, in JSON help
payloads and in tests. `SpectreHelpPresenter` uses its console's width: a width
passed to `SpectreCommandConsole` as given, otherwise the terminal width less
one column, or 100 columns when redirected. Options with an empty default no
longer show `[default: ]`.

Tests that compare complete help text must be updated for the new spacing.
`CommandHelpFormatter.Format(..., CommandTextContext, ...)` gains an optional
`width` parameter (at least `CommandHelpFormatter.MinimumWidth`, 20).

## Generator diagnostics link to documentation

Each `RCLI9xxx` source generator error now has a help link to its section in
[`docs/guides/command-line/diagnostics.md`](https://github.com/Runic-Artifex/runic-cli-sdk/blob/main/docs/guides/command-line/diagnostics.md).
Their messages no longer end with a period, following the Roslyn message
convention; IDs, titles and severities are unchanged.

## Unsafe fault messages keep their code

A `CommandFault` whose message contains technical content (an exception type
name, an absolute internal or UNC path, or a drive-letter path) used to be
replaced entirely by `RCLI5000: The command failed unexpectedly.`, losing the
application's code. The code is now kept when it is well-formed
(`[A-Z][A-Z0-9_.-]*`, at most 64 characters), including application-range
`RCLI8xxx` codes and application prefixes such as `RAS1001`. Only the message
is replaced, with `The command failed; details were redacted.`, in both JSON and
human output. Details are still redacted value by value, and exit codes are
unchanged.

A malformed code still collapses to `RCLI5000`. A code longer than 64
characters is now treated as malformed instead of being truncated. Clients that
treated `RCLI5000` as the signal for a redacted message should check for the new
message or rely on the code alone.
