# Runic Command Line 0.15.0

## Upgrading from 0.14

Nothing is removed. These changes can still need action (#114, and the Command Line specification's third and fourth rounds):

| Change | Who is affected | What to do |
| --- | --- | --- |
| **Breaking:** a global option that is not a flag or a single value fails catalog validation with `RCLI0028` from `Build`; `GlobalOption` no longer throws `ArgumentException` | Catalogs that declare such a global option, and code that caught the exception | Declare `CommandArity.Zero` or `CommandArity.ExactlyOne`, or declare the option on each command. Catch `CommandCatalogValidationException` instead. |
| **Breaking:** `RCLI0019` also fails a command option with a global option's ID that allows repeats, is required or sensitive, reads another environment variable or declares other choices than the global option declares, or accepts negative numbers while the global option does not | Catalogs whose command option restates a global option with different settings; they built before | Give the command option the global option's settings, leave out the environment variable and choices to inherit them, or give the options different IDs. |
| **Breaking:** choices on a flag fail catalog validation with `RCLI0029`, and the generator reports `RCLI9047` for `Choices` on a `bool` option | Catalogs that declared choices on a flag; they had no effect | Remove the choices. |
| **Breaking:** an environment variable on an option whose arity needs two or more values fails catalog validation with `RCLI0030` | Catalogs with such a fallback; it bound one value, below the option's minimum | Remove the variable or lower the minimum to one. |
| A global option before the command path whose value is missing is `missing-option-value` at the token after it, as after the command path: `--profile --help` and `--profile` alone no longer give `unknown-command` at 0 | Scripts that relied on the code or kind of that error | None for valid command lines; the exit code (2) is unchanged. |
| A root command's name is no longer suggested for a mistyped command: with a root command `run` that takes no positional tokens, `tool run` and `tool rnu` report `unexpected-argument` (`RCLI1006`) instead of `unknown-command` (`RCLI1002`) suggesting `run`, a spelling that does not name it | Scripts that relied on the code or kind of that error | None; the exit code (2) is unchanged. Name the command's input instead; `tool run` never ran it. |
| The usage hint of the root command (`RootCommand`, `[RootCommand]`) is root help's usage line and `<application> --help`: a usage error in it ends with `Usage: tool [command] <target> [options]` and `Run "tool --help" for more information.` instead of `Usage: tool run [options]` and `Run "tool run --help" …`, which named a command the command line cannot name and left out its arguments | Tests that compare the standard error of a root command's usage error | Update the expected text. JSON output, the exit code (2) and the diagnostics are unchanged. |
| A token that looks like a negative number is checked against the argument that positional binding gives it, which leaves room for the minimums of later arguments: with `points` (one or two values) and `delta` (one value, negative numbers), `plot x -3` binds `-3` to `delta` instead of reporting `unknown-option` | Commands with an optional or multi-value argument before one that accepts negative numbers | None; such command lines now bind. |

## A protocol corpus that any implementation can run (D080, R7 G12)

The `runic.commandline/1` specification and its corpus no longer rely on the .NET test runner for anything they
check. Nothing changes for applications: the library, its JSON output and its reader behave as in 0.14.

- **Value-normative examples.** The examples are compared by JSON value. Byte identity is required only of a writer
  that claims the named `dotnet` escaping profile, which the protocol README now defines exactly, including the fault
  detail order (UTF-16 code units). Another writer may escape differently and still conform.
- **Writer cases.** `protocol/writer-cases.json` gives the inputs that produce each example, and cases for the
  sanitization steps, so a writer in another language can replay them. A tenth example,
  `examples/fault-details.json`, covers detail sanitization, ordering and escaping outside ASCII.
- **Sanitization, specified.** The README now gives the exact algorithm for faults and diagnostics, instead of
  calling it a heuristic: control-character runs, truncation on scalar boundaries, the 32-detail cap, which duplicate
  wins, diagnostic redaction, and which replacement texts are fixed and which may be localized.
- **Reader reasons in check order.** The strict reader's 30 rejection reasons, the order in which it checks a frame,
  and so which reason wins when a frame breaks several rules. The manifest lists them, with two more limits (64
  diagnostic path segments, 2,048 help URI characters) and the sample payload contracts. The semantic and wire corpora
  grow from 31 and 20 cases to 77 and 34. They add single-cause cases, two-violation precedence cases, depth and
  failure-data boundaries, and an explicit client context on every case.

## The rest of the grammar, specified (D080, R7 G13)

`specs/command-line/grammar.md` now covers what only the .NET parser defined. Parsing is unchanged.

- **Parse order.** Output selection is checked over the whole command line first. The specification also gives where
  an unknown command is reported (index 0, also after leading options), and how the checks after the last token are
  ordered.
- **One error diagnostic** per parse, and the order of options in a result.
- **Help.** The `help` word, `unexpected-root-help-argument` (`RCLI1013`), and help for an invoked group.
- **Catalog features.** Required options (`RCLI1012`), environment fallbacks with their Boolean words (`RCLI1014`),
  choices and their case matching (`RCLI1015`), global options, and the negative-number token grammar.
- **Diagnostics.** The arguments of every kind, the suggestion algorithm, the message keys, and the UTF-16 limits for
  echoed tokens and short options.
- **Neutral names.** Neutral terms replace .NET names in the normative text. `RUNIC_COMMANDLINE_DEBUG=1` is the
  cross-language developer opt-in. The codes `RCLI2001`, `RCLI3000` and `RCLI3001` in the examples are marked
  illustrative.

The fixture catalog gains a global option, a `deploy` command with these option features, and a help-only group.
The grammar corpus grows from 50 to 103 cases and the output-classification corpus from 26 to 31. The Windows slash
dialect still has no corpus.

## Old-name guards for the Runic Artifex rename (D079.11)

`Runic.CommandLine` now ships build logic: `buildTransitive/Runic.CommandLine.targets` imports the rename's old-name
guards, `Runic.CommandLine.RenamedNames.targets`, generated from `eng/rename/old-names.json`. They fail a build that has
a package of a former ID in its package graph (`RCLI7001`), sets a former MSBuild name (`RCLI7002`) or has a former
environment variable set (`RCLI7003`), each once, with an error that names the new name; the package error also names
`rax migrate`. This release lists no name, so nothing reports them yet; the rename release fills the lists, and the
guards stay through 1.0.x. `buildTransitive/Runic.CommandLine.props` gives the errors their help links at the release
tag.

## The reader rejects unpaired surrogate escapes as malformed JSON (#111)

`CommandJsonEnvelopeReader.Read`, and `CommandTestEnvelope.Read` through it, threw an uncaught
`InvalidOperationException` for a JSON escape that decodes to an unpaired UTF-16 surrogate (`"\ud800"`) in the request
ID, a fault message or an unknown member name. It now reports `malformed-json` for such an escape anywhere in the frame,
in a value or a member name, the payload and unknown members included: check 8 of the protocol's strict reading now
follows the I-JSON rule (RFC 7493). A frame with an unpaired surrogate escape only in a payload value was accepted
before and is rejected now, and one in failure data is `malformed-json` instead of `invalid-failure-data`; a
conforming writer never emits either. `CommandFailureData.Create` still refuses an unpaired surrogate with
`invalid-failure-data`. An escaped surrogate pair (`"\ud83d\ude00"`) is still accepted. The wire corpus grows
from 34 to 41 cases.

## Global options, fallbacks, choices, negative numbers and signals (#114)

The grammar and hosting specifications described these .NET behaviours as they were (#113, #115). They are now
decided, and the specifications and corpus follow them.

- **Global option arity** has a catalog code, `RCLI0028`, like the other catalog rules.
- **A command option with a global option's ID** must agree with it completely (`RCLI0019`, see the table above).
  Its help no longer loses to the global option's: each member of its `CommandHelp` that it sets wins, so a
  generated option keeps its description, path kind, bounds, `Requires` and `ConflictsWith`. The global option's
  help fills in the members it leaves unset. Before, a global option's help replaced the command option's whole
  help.
- **A global option's value before the command path** ends where it would after it, so `--profile --help` and
  `status --profile --help` both report `missing-option-value` at the `--help` token.
- **Negative numbers** are detected by the binding rule, as the table above describes.
- **Environment fallbacks** that could not satisfy an option's arity are a catalog error (`RCLI0030`), and
  **choices on a flag** are too (`RCLI0029`, generator `RCLI9047`).
- **Signal registration** that fails with an `IOException`, `UnauthorizedAccessException` or `Win32Exception` is
  handled like an unsupported platform: that signal keeps the runtime's default handling and the invocation runs.
  Before, only `PlatformNotSupportedException` was caught, and any other failure escaped from `CommandApp.RunAsync`.
  Prompts on a terminal register their cursor-restoring handlers the same way.

The grammar corpus grows from 109 to 116 cases. `grammar.option.global-value-before-command-takes-help` is replaced by
`grammar.option.global-value-before-command-takes-help.v2`, and the fixture catalog gains a `plot` command.

## Default and root commands, input validation and catalog validity, specified (R7 RU8 groundwork)

`specs/command-line/grammar.md` now specifies the catalog features that only the .NET library defined, as it
implements them:

- **Default and root commands** (`DefaultCommand`, `RootCommand`): when they apply, help for them, the mistyped-command
  rule that reports `unknown-command` with a suggestion instead of `unexpected-argument`, and `RCLI0018`.
- **Declared choice spellings**: a value binds as the declared spelling, and the generator declares an enum's members
  as written (`Fast`, not `fast`).
- **Input validation** after parsing: `Requires` and `ConflictsWith`, path kinds and `MustExist`, and `Minimum` and
  `Maximum`, with their `RCLI2002` diagnostics, arguments and order, and the number text of the bounds.
- **Catalog validity**: the codes of the rules the grammar names, `RCLI0028` also for a global option that repeats,
  is required or is sensitive (which `GlobalOption` cannot declare), that a catalog may report one or every issue, and
  that text-key checks are the library's own rules.

**Fixed:** the unnamed root command's name was a candidate for the mistyped-command suggestion, although it is no
command spelling (see the table above). The slash dialect's command suggestions leave it out too.

A new corpus file, `catalog-features-corpus.json`, has named catalogs and 68 cases. Its rows parse, validate the
input after parsing (the driver's new `cl.validate` operation) or only build their catalog (`cl.catalog`). The .NET
adapter passes 65 of them; the three global option settings it cannot declare are unsupported. The conformance corpus
grows from 297 to 365 cases.

## Help text, human output and payload number text, specified (R7 RU8 groundwork)

The specifications now cover what Runic Command Line writes for people, as the .NET library writes it. Nothing changes
for applications.

- **Help text** (`specs/command-line/help.md`, new): the width (the terminal's minus one, else 80; at least 20), terminal
  cells and wrapping, the usage line, descriptions and long descriptions, the sections and their term column, the
  `(default)` marker, the notes (`[required]`, `[default: …]`, `[choices: …]`, `[env: …]`, path kinds, bounds and
  relations) and their text keys.
- **Human output** (`hosting.md`): a success's diagnostics on standard error before its result, the text result's
  final line feed (empty text writes `"\n"`) and the unit result's silence, a failure's diagnostic lines, fault line,
  help link lines (`hints.help-link`) and usage hint, and a failure's own human output.
- **Binding diagnostics** (`grammar.md`): a value that does not convert has the message of its kind; the binder's
  exception text with the .NET type name (`expected Int32`) is never written.
- **Number text** (protocol README): how the `dotnet` escaping profile writes a double, with a new example,
  `examples/number-text.json`, its writer case and the sample payload type `sample.measurement/1`.

Two new corpus files, `help-corpus.json` (16 cases; 9 of them are the .NET reference snapshots the Rust producer
tests against) and `human-output-corpus.json` (24 cases), run through the driver's new `cl.help` and `cl.human`
operations and its new `presenter` role. The conformance corpus grows from 365 to 407 cases, and the .NET adapter
passes all of them but the three it already reported unsupported.

## Gaps the Rust and C++ producers found, specified (Command Line specification, fourth round)

The Rust and C++ producers that follow the third round found places where the specifications left the behaviour
open. The specifications now give what Runic Command Line does, with corpus rows that show it.

- **Typed values** (`grammar.md`, "Input validation"): relations and paths are checked before a binder converts
  values, and each value is converted before its bounds are checked. With an integer option whose maximum is 65535,
  `65535.5` is `invalid-integer` (`RCLI2005`), not `out-of-range`; without a conversion the value is read as a number
  and is `out-of-range`. A `validate` row of the catalog features corpus may now give `conversions`, which the
  driver passes to `cl.validate`; these rows require the feature `binding:integer-conversion`.
- **Empty paths**: an empty value of an option or argument with a path kind is malformed everywhere, as a value with
  U+0000 is.
- **The `RCLI5000` hint** follows the fault's code whatever the failure's category, also after a writer replaced an
  invalid code, and a failure that gets it is written without its usage hint and its own human output.
- **The root command's usage hint** is root help's usage line and help command. **Fixed:** .NET wrote the root
  command's name, which the command line cannot name (see the table above).
- **Help links** in human output are written as the writer writes `helpUri`: as given, or in the `dotnet` profile's
  normalized form, which the new rows that change a link require (`escaping-profile:dotnet`).
- **A payload-shaped JSON output alias** (`jsonOutputAliasShape` in a corpus catalog): standard output carries the
  failure's data or nothing, and standard error the diagnostics and either the failure's own text or the fault line
  with its help link, usage hint and `RCLI5000` hint.
- **The Windows slash dialect** has corpus rows for its help and usage hint (catalog member `dialect`, feature
  `dialect:windows-slash`).

The conformance corpus grows from 407 to 436 cases: the catalog features corpus from 68 to 77, the help corpus from
16 to 19 and the human output corpus from 24 to 41. The .NET adapter passes all of them but the three it already
reported unsupported.
